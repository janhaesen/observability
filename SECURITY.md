# Security Policy

## Reporting a vulnerability

If you believe you have found a security vulnerability in `observability`, please avoid opening a public issue before the maintainers have had a chance to assess it.

Preferred approach:

1. Use GitHub's private vulnerability reporting or repository security advisory flow if it is enabled for this repository.
2. If private reporting is not available, contact the repository owner through a private GitHub channel before disclosing details publicly.

Please include:

- a clear description of the issue
- affected versions or modules
- reproduction steps or proof of concept
- impact assessment if known

## Response expectations

The project will try to:

- acknowledge the report
- assess severity and scope
- prepare a fix or mitigation
- coordinate disclosure once affected users have a reasonable upgrade path

## What to report privately

Report privately if the issue could reasonably:

- expose sensitive data
- enable unauthorized access
- bypass trust, integrity, or transport guarantees
- cause unsafe default behavior in production use

For non-sensitive bugs, documentation problems, or general hardening ideas, use the normal public issue and pull request flow.
